# Architecture

This is a static-first Astro starter for content-led marketing sites. It ships static HTML, local content, and only the JavaScript needed for consent and an optionally enhanced contact form.

## Directory map

| Path                              | Responsibility                                                                                                              |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `src/pages/`                      | Public routes and static endpoint routes                                                                                    |
| `src/layouts/BaseLayout.astro`    | Document shell, canonical/social metadata, optional JSON-LD, configured CSS properties, header, footer, and consent manager |
| `src/components/seo/JsonLd.astro` | Safely serializes page-level Schema.org JSON-LD supplied by a route or layout consumer                                      |
| `src/components/site/`            | Reusable site components and the internal design-system preview                                                             |
| `src/config/site.config.ts`       | Typed client identity, features, palettes, semantic mappings, and theme values                                              |
| `src/content/`                    | Local Markdown and MDX source content                                                                                       |
| `src/content.config.ts`           | Content Collection loader and Zod schema                                                                                    |
| `src/styles/global.css`           | Tailwind integration, build-time breakpoints, global styles, and CSS fallbacks                                              |
| `public/brand/`                   | Public SVG logo and icon placeholders                                                                                       |
| `tests/`                          | Unit configuration tests and browser smoke/accessibility tests                                                              |
| `docs/`                           | Architecture, semantic DOM, handoff, content, design-system, integrations, and testing guidance                             |

## Route model

`src/pages/index.astro` currently serves the no-index internal design-system preview. The legal pages are generated by `src/pages/[...slug].astro` from non-draft content entries with a `slug`. `robots.txt` is generated by its own endpoint and the sitemap is configured in `astro.config.ts`.

At client kickoff, move the preview to `/design-system` and restore `/` as the marketing homepage. Follow [client setup](client-setup.md) so sitemap filtering and tests remain correct.

## Configuration flow

`site.config.ts` is the typed home for client decisions that are safe to expose in static output. `BaseLayout.astro` resolves configured semantic colours and writes them as CSS custom properties. Components consume stable semantic Tailwind roles such as `bg-role-primary` instead of client hex values.

Breakpoints are intentionally excluded from `site.config.ts`: Tailwind compiles them into media queries at build time. Their source of truth is `global.css`.

## Metadata and structured data

`BaseLayout.astro` owns the canonical URL, description, Open Graph metadata, and Twitter card metadata. It accepts an optional `image`, `ogType`, and `structuredData` prop so individual public routes can supply accurate page data without duplicating document-head markup. `structuredData` is intentionally suppressed on `noindex` pages.

Read [DOM architecture](DOM_ARCHITECTURE.md) before adding content-bearing components or Schema.org data. It is the repository contract for landmarks, headings, media, answer-oriented content, and structured data.

## Content flow

Astro Content Collections load `src/content/pages/**/*.{md,mdx}`. The Zod schema validates frontmatter at check and build time. A page is public only when it is not a draft and supplies a `slug`; `es/home` is reserved for the sample homepage content.

## Client JavaScript boundary

The starter does not include a client UI framework, global state store, scroll library, or transition library. The consent manager and contact form each own their small client script. New browser JavaScript should stay local to the component that requires it and should preserve a usable non-JavaScript path where possible.

## Static-hosting boundary

The project uses `output: 'static'`. There is no server adapter, API route, database, or custom form backend. Add server rendering only after the hosting, privacy, caching, and data requirements are explicit.
