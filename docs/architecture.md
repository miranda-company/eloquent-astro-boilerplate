# Architecture

This is a static-first Astro starter for content-led marketing sites. It ships static HTML, local content, and only the JavaScript needed for consent and other approved component-scoped enhancements.

## Directory map

| Path                                 | Responsibility                                                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `src/pages/`                         | Public routes and static endpoint routes                                                                                 |
| `src/layouts/BaseLayout.astro`       | Document shell, canonical/social metadata, optional JSON-LD, Figma token stylesheet, header, footer, and consent manager |
| `src/components/seo/JsonLd.astro`    | Safely serializes page-level Schema.org JSON-LD supplied by a route or layout consumer                                   |
| `src/components/site/`               | Reusable site components and the internal design-system preview                                                          |
| `src/config/client-config.ts`        | Typed client identity, features, brand assets, navigation, and site metadata                                             |
| `src/config/figma-tokens.json`       | Checked-in export of approved Figma variables and mode values                                                            |
| `src/config/figma-tokens-adapter.ts` | Validates the export and emits Figma tokens as CSS custom properties                                                     |
| `src/content/`                       | Local Markdown and MDX source content                                                                                    |
| `src/content.config.ts`              | Content Collection loader and Zod schema                                                                                 |
| `src/styles/global.css`              | Reset/base rules, focus defaults, shared layout foundations, and responsive wrapper rules                                |
| `src/styles/breakpoints.css`         | Shared build-time custom-media aliases for responsive viewport thresholds                                                |
| `src/styles/button.css`              | Shared button base and variants imported by their consumers                                                              |
| `public/brand/`                      | Public logo and icon placeholders (`.svg`, `.png`, `.jpg`, or `.jpeg`)                                                   |
| `tests/`                             | Unit configuration tests and browser smoke/accessibility tests                                                           |
| `docs/`                              | Architecture, semantic DOM, client workflow/handoff, content, design-system, integrations, and testing guidance          |

## Route model

`src/pages/index.astro` currently serves the no-index internal design-system preview. Public content pages are generated by `src/pages/[...slug].astro` from non-draft entries with a `slug`. Entries with `template: legal` compose `LegalPageLayout.astro`; other entries use the standard article route. `robots.txt` is generated by its own endpoint and the sitemap is configured in `astro.config.ts`.

At client kickoff, move the preview to `/design-system` and restore `/` as the marketing homepage. Follow [client setup](client-setup.md) so sitemap filtering and tests remain correct.

## Configuration flow

`client-config.ts` is the typed home for client identity and operational decisions that are safe to expose in static output. Figma is the source of truth for design tokens; `figma-tokens.json` is its checked-in export, and `figma-tokens-adapter.ts` validates it and emits mode-aware CSS custom properties at build time. Component styles consume Figma-derived variables such as `var(--color-text-default)`, never client hex values. `.wrapper` uses Figma's `max-width-2xl` and `spacing-wrapper-default` variables.

Breakpoints are intentionally excluded from client configuration: `breakpoints.css` is their build-time source of truth. The shared wrapper rules live in `global.css`; responsive details stay with the owning module and use the same custom-media aliases.

Google Font family names and normal weights remain Figma tokens. `BaseLayout.astro` emits the generated preconnect and stylesheet links with `display=swap`; italic loading requires a future explicit Figma token contract.

## Metadata and structured data

`BaseLayout.astro` owns the canonical URL, description, Open Graph metadata, and Twitter card metadata. It accepts an optional `image`, `ogType`, and `structuredData` prop so individual public routes can supply accurate page data without duplicating document-head markup. `structuredData` is intentionally suppressed on `noindex` pages.

Read [DOM architecture](DOM_ARCHITECTURE.md) before adding content-bearing components or Schema.org data. It is the repository contract for landmarks, headings, media, answer-oriented content, and structured data.

## Content flow

Astro Content Collections load `src/content/pages/**/*.{md,mdx}`. The Zod schema validates frontmatter at check and build time. A page is public only when it is not a draft and supplies a `slug`.

Legal pages remain local MDX content. `LegalPageLayout.astro` owns their single `h1`, page metadata handoff, optional review notice, optional definition-list summary, responsive table of contents, and prose column. The content entry owns its approved legal copy and the stable IDs used by the contents navigation. Footer destinations come from `siteConfig.legal.pages` so the same links are not duplicated in a component. When enabled, the consent-preferences button is a separate in-page action placed beside the legal navigation in a shared wrapping layout.

## Client JavaScript boundary

The starter does not include a client UI framework, global state store, scroll-jacking library, or transition runtime. GSAP and ScrollTrigger are available as an unreferenced component-scoped foundation; the default build emits neither until a component imports `src/scripts/animation/gsap.ts`. `ConsentManager.astro` owns its small client script. New browser JavaScript should stay local to the component that requires it and should preserve a usable non-JavaScript path where possible. Read [animation](animation.md) before adding motion.

`siteConfig.features.contactForm` and `PUBLIC_FORM_ENDPOINT` are intentionally retained as disabled integration placeholders. No contact-form pattern ships today. Add one only after the client approves its provider, privacy disclosures, submission path, and non-JavaScript behavior.

## Static-hosting boundary

The project uses `output: 'static'`. There is no server adapter, API route, database, or custom form backend. Add server rendering only after the hosting, privacy, caching, and data requirements are explicit.
